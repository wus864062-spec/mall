# Biz：金额、档位、锁仓

本目录是规则层。改奖励 / 锁仓 / 档位时先看这里，再改 `ispay.go`、`dualtrack.go`。

## 金额

| 资产 | 内部单位 | 约定 |
| --- | --- | --- |
| USDT | fen，`1 USDT = 10000`（`UstdScale`） | 只截断，不四舍五入 |
| IsPay | micro，`1 枚 = 1e8`（`IspayMicroPerCoin`） | 只做整数除法 |

展示用 `FormatUstd` / `FormatIspay`、前端 `fmtUstd` / `fmtIspay`，不要对金额 `Math.round`。给人看时 USDT 写 U、IsPay 写枚，两边都不写「分」。

## 当前档位 vs 锁仓

目录档位：1000 / 2000 / 3000 / 6000 / 12000 / …。

**当前档位** = 认购总额向下取整到不超过总额的最高档（`EffectivePackageFen`）。用于钱包「当前档位」、动态奖励日封顶、管理奖资格。

**锁仓** = 当前档位折 IsPay +（总额 − 档位）的超额折 IsPay。同兑换价下等于认购总额折枚数（`CoinsMicroFromPay`）。

| 认购 | 档位 | 超额 | 锁仓 |
| --- | --- | --- | --- |
| 1000 + 1000 = 2000 | **2000** | 0 | 折(2000) |
| 1000 + 3000 = 4000 | 仍是 **3000**（不到 6000） | 1000U 折进锁仓 | 折(3000)+折(1000) |
| 3000 + 3000 = 6000 | 升到 **6000** | 0 | 折(6000) |

兑换价由主品类天数决定，整数截断：300 天 1200U/枚、600 天 1000U/枚、750 天 800U/枚。

公式：`锁仓 micro = 认购总额 fen * 1e8 / 兑换价 fen`。不要把档位当成认购总额，也不要把超额当成新档位。

## 静态释放

锁仓本金按 300 / 600 / 750 天摊还：`每日枚数 = 锁仓 / 天数`，最后一天吃余数。

当日释放市值 = 当日枚数 × **当前** IsPay 单价，再 `SplitHalf`：一半 USDT，剩余折免费 IsPay。进可提现，不扣提现额度。

第一次有档位时打开静态窗。**再认购（含升档、换天数）不把 `StaticReleasedDays` 归零**，按新锁仓 / 当前天数继续摊。启动时 `resyncAllWeb3Locks` 只对齐枚数，不补提现额度、不倒冻结。

入口：`data.syncWeb3LockLocked`（下单 / 购物车一次结清 / 启动对齐）。

购物车一次买多套餐：用各套餐实付合计当前认购总额。档位 / 动态奖励日封顶 / 管理奖看 `EffectivePackageFen(合计)`；锁仓看 `CoinsMicroFromPay(合计)`。超额（合计 − 档位）按同一兑换价折 IsPay，不是新档位。

## 左右区 vs 大小区

安置只有**左区 / 右区**（`TrackLeft` / `TrackRight`）。填邀请人钱包地址后按**双轨自动占位**：先左后右，已安置的人同一侧往后排。万能邀请码（默认 `0xD0E440F03b2b0CE452AE6EDA56750b97Ef7A4b9F`，可用环境变量 `MALL_MASTER_INVITE`）只能用一次，用后成为根节点、不挂任何人下面。

**大小区**要等左右链上有人认购（`PerfFen`）才有：业绩大的为大区，小的为小区（`AreasFromPerf`）。用链上成员认购合计，不用自己的认购。两侧都是 0 就还没有大小区。对碰体积仍是 `min(左, 右)`。

## 动态奖励日封顶

档位表默认仍是 1000→600、2000→1200、3000→1800、…（`PairCapFen`）。后台 **配置项 → 日封顶** 可按档改这个数，改完立刻用于直推/对碰/管理奖合计日封顶和提现额度（`PairCapFenWith`），锁仓仍按认购总额折 IsPay。填 0 表示该档当天动态奖不发、也不发提现额度。

**当日**直推奖 + 对碰奖 + 管理奖（折半入账前的奖励 fen）加总，不得超过该档封顶。上海日历换日清零。额度用完后未发部分丢掉，不对碰业绩滚日；对碰按 `min(左区业绩, 右区业绩)` 消耗 `SettledPairFen`（小区=较小侧，不是固定右区）。

无档位时对碰/管理奖为 0；直推仍按 10% 发，但会计入当日已用额度，当天再升档后剩余额度变少。

## 冻结与提现额度

动态奖默认进冻结。提现额度按**当天最高档**发一次：配置项里的 `PairCapFenWith(EffectivePackageFen(认购合计))`。2000 档默认当天发 1200；同日再买仍是 2000 档不加；升到 3000 档才补到 1800。换日**不会**自动再发，除非再下一单。金额看配置后的档位表，不用各件 600 相加。

600 是折前合计（USDT 一半 + IsPay 一半），不是解冻 600 USDT。额度没用完时，后续动态奖先填可提现并扣额度；超额进冻结。下单时也会按剩余额度 FIFO 解冻已有冻结：**先扣最早那天的批次**，第二天的冻结先不动。买单、同日再冻都不改该批次 `CreatedAt`（不重置 72 小时倒计时）。

冻结按入账日批次满 72 小时作废，不进可提现；各日倒计时互不影响，先到期的先清。额度本身不过期。提现只扣可提现。取消订单的解冻回退本次不做。

## 提现热钱包

USDT 提现：先用 `MALL_HOT_WALLET_KEY` 从 BSC 热钱包 `transfer` 净额（申请额 − 手续费）到用户登录地址，成功后再扣可提现。手续费留在热钱包。未配私钥或链上失败都不扣账。IsPay 提现仍只走账本。私钥不要写进配置文件。
